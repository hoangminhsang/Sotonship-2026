## Amendments of 18 Oct 2026, evening: the one-page dashboard (read this second)
`ui/index.html` is now the demo page. The seven-screen page of the 17 and 18 Oct drafts moved to `ui/details.html`. Where this block and an older line disagree, this block wins.
- **Page.** `index.html` has a cover ("Redline", "Press any key to start") and three views: Live run, Results and Proof. Keys `1`, `2` and `3` open them, and `#v=live|results|proof` in the address opens one. Live run is an n8n-style flow of nodes and wires. "What just happened" is built from one real run in `window.DEMO` and names its source when that run is not the one the badge names. The candidate chips come from the gate verdicts in `window.DEMO`. One badge says real or scripted.
- **Words.** Every word on screen lives in `ui/copy.js`, which holds no digit. `index.html` reads the `page` block of `window.COPY`. `details.html` and `app.js` read the other blocks.
- **Numbers.** A number comes only from `window.DEMO` (`ui/data/demo.js`, made by `ui/export.py`) or from `window.LIVE` (`ui/data/live.js`, made by `ui/bridge.py`, schema `ui-live/1`). The Proof and Results views read `DEMO` only. A scripted `LIVE` feed never replaces real `DEMO` data: the chips follow `LIVE` only while a real run (LIVE, REPLAY or SAVED) is in progress, and the log check never reads `LIVE`. `tests/test_ui_index_page.py` guards these rules.
- **Live feed.** `index.html` re-inserts `data/live.js` as a script tag every 1000 ms. It does not load `pipeline.js`, `app.js` or `replay.js`. It uses `pipeline-glyphs.js` for the node glyphs.
- **Run bar.** On a page served over http, the bar calls the bridge: `GET /api/session` (returns a token), `GET /api/status`, `POST /api/run` with the header `X-Redline-Token` and the JSON `{kind: demo|live-short|live-full|models, model, parallel}` (answers 202, 400, 403 or 409), and `POST /api/stop`. The bridge listens on `127.0.0.1` only. The page starts no command itself: it asks, and the bridge starts the fixed command. Server side: lane W. The page treats any answer but 202 as "could not start". From `file://` the bar is hidden. The page's CSP is `connect-src 'self'`, and its only `fetch` calls go to `/api/`.
- **Old page.** §1 (screens and keys), §8 to §10 (DOM, CSS, `app.js`) and §13 (type scale) describe `details.html`. `index.html` has its own styles in its `<style>` block.

- Type **[amended 18 Oct: sizes now follow §13]**: Cormorant Garamond 300 for screen titles and hero counts ("12 of 24"); serif italic 300 sparingly for one-line quotes ("The machine gives evidence. A person decides."). Inter 400 body, Inter 500 for labels and emphasis. Labels in sentence case, NOT tracked all-caps eyebrows. ## 13. Owner's design direction, 18 Oct 2026 (binding; it wins over §9 and §12 where they differ)
**[Applies to `details.html`. `index.html` sets its own sizes in its `<style>` block.]**
The owner's words: do not complicate the dashboard; medium fonts, not many large ones; easy to understand at a glance. In rules:
1. **Type scale.** The stage is 1920×1080. Labels are 22 px, the minimum for any text. Body text is 26 px. A screen title is 40 px. A screen has at most ONE key number at 56 px (for example "12 of 24"). Nothing is larger than 56 px. Do not add a fifth size.
2. **Medium weights.** Cormorant Garamond 300 and 400 for the title and the key number; Inter 400 for body and 500 for labels. No bold. Do not use many large type sizes on one screen.
3. **Status tags** sit on ONE compact line: the data-status chips of the header (REAL, SAMPLE, PENDING, each with its word) and the mode word sit side by side, not stacked in a column.
4. **Warnings** are ONE line per screen: a count and a pointer to the export report ("N warnings. The export report lists them."). Integrity warnings are counted in the same line. The full list stays in the export output, not on the page.
5. **Pipeline glyphs** are about 80×60 px on screen (drawn in a 120×90 viewBox and scaled). Each node has one caption and ONE fact line. Facts are short, about 50 characters at most.
6. **One question and one answer per screen.** The title asks or names the question; one block answers it. A second block only supports the answer. Anything else goes behind a key or a drawer.
7. State is never carried by colour alone: shape, pattern and a word, as in §1. These rules change size and density only.
8. A check for QA: at 1366×768 the smallest text is still readable (22 px on the stage scales to about 16 px), and no screen scrolls except the places marked `[data-scroll]`.
Note: the 56 px key number replaces the 220 px "big number" of the carousel. The carousel keeps its own scale; only the dashboard follows this section.
